# Vekha — от задачи к результату

Трекер задач и проектов для продуктовых команд: очереди, доски, спринты,
воркфлоу, автоматизации, отчёты и права. Приложение работает целиком: данные
живут в базе, изменения видят все участники, а интерфейс собран по
дизайн-системе Vekha v2 — светлая и тёмная темы, drag-and-drop, командная
палитра.

## Быстрый старт

```bash
npm install
```

```bash
npm run db:migrate
```

```bash
npm run seed
```

```bash
npm run dev
```

Интерфейс поднимется на `http://localhost:5173`, API — на `http://localhost:4180`.

Наполнение создаёт демонстрационное пространство «Норд Софт». Вход:

| Учётная запись | Роль |
| --- | --- |
| `anna@nordsoft.ru` | админ |
| `dmitry@nordsoft.ru`, `elena@nordsoft.ru` | лид |
| `marina@nordsoft.ru`, `igor@nordsoft.ru`, `pavel@nordsoft.ru` | участник |

Пароль у всех — `vekha2026`. Он задаётся переменной `SEED_PASSWORD` и годится
только для демонстрации: перед реальным использованием смените пароли и
`JWT_SECRET` в `.env`.

Начать с чистого листа можно без наполнения — тогда первый зарегистрированный
человек становится администратором и приглашает остальных по ссылке.

## Что умеет

| Экран | Маршрут | Что делает |
| --- | --- | --- |
| Главная | `/` | Показатели, список «требует внимания» с причинами, мои задачи, активные проекты, сводка спринта, упоминания и лента активности |
| Задачи | `/tasks` | Серверные фильтры, сортировка по девяти колонкам, переключаемые колонки, изменение ширины мышью, поиск, чипы-фильтры, множественный выбор и массовые действия, пагинация |
| Задача | `/tasks/:key` | Описание и заголовок с редактированием, подзадачи с прогрессом, вложения, комментарии с упоминаниями, история изменений, связи, наблюдатели, переходы по воркфлоу |
| Доска | `/board` | Канбан с перетаскиванием, индикатором вставки, лимитами WIP, сворачиваемыми колонками и фильтрами по очереди, спринту и человеку |
| Спринты | `/backlog` | Планирование: перенос из бэклога, ёмкость команды, нагрузка по людям, предупреждения о перегрузке, запуск и закрытие спринта |
| Очереди | `/queues` | Очереди с владельцем, воркфлоу, уровнем доступа и счётчиком задач; создание и настройка |
| Проекты | `/projects` | Карточки проектов с реальным прогрессом, командой и сроками |
| Проект | `/projects/:name` | Обзор с вехами и рисками, список задач, диаграмма Ганта по настоящим датам |
| Фильтры | `/filters` | Конструктор условий, язык запросов с проверкой на сервере, сохранённые, избранные и командные фильтры |
| Отчёты | `/reports` | Burndown, пропускная способность по неделям, кольцо статусов, нагрузка, метрики спринтов, просрочки |
| Команды | `/teams` | Составы команд, роли, загрузка; добавление и исключение участников |
| Настройки | `/workflow` | Статусы и переходы (список и схема), поля задачи, матрица прав, конструктор автоматизаций, шаблоны, колонки доски, участники и приглашения |

Поверх экранов: командная палитра (`⌘K` / `Ctrl+K` или `/`), создание задачи
по `C`, всплывающие уведомления, переключение темы с сохранением выбора и
живое обновление данных через Server-Sent Events — изменение, сделанное
коллегой, появляется без перезагрузки страницы.

## Как это устроено

### Роли и права

Четыре роли: админ, лид, участник, гость. Права заданы матрицей и
редактируются на экране настроек; проверка идёт на сервере, поэтому снятая
галочка закрывает действие в API, а не просто прячет кнопку.

Вход — по почте и паролю (bcrypt), токен лежит в httpOnly-куке и недоступен
из JavaScript страницы. Новые участники приходят по ссылке-приглашению;
письма приложение не отправляет, ссылка копируется в интерфейсе.

### Воркфлоу

У каждой очереди свой воркфлоу: набор статусов и разрешённых переходов.
Задача не может попасть из статуса в статус, если перехода нет, — правило
действует и в карточке, и при перетаскивании на доске. Статусы делятся на
четыре категории (`todo`, `inprogress`, `done`, `blocked`), от которых
зависят цвет и попадание в отчёты.

### Автоматизации

Правило — это триггер, условие и список действий, всё хранится в базе:

```json
{ "all": [{ "field": "status", "op": "eq", "value": "Review" }] }
{ "actions": [{ "type": "notify", "role": "manager" }] }
```

Триггеры: создание задачи, смена статуса, закрытие задачи и ежедневный
прогон. Действия: уведомить, поднять или сменить приоритет, сменить статус,
назначить исполнителя, добавить наблюдателя, тег или комментарий. Формат
намеренно узкий — правило нельзя превратить в произвольный код.

### Язык запросов

Конструктор фильтров всегда собирает строку запроса, её видно и можно править
руками:

```
queue = VEKHA AND status = Review
assignee = currentUser() AND deadline <= endOfWeek()
(priority in (Critical, High) OR tag = bug) AND status != Done
```

Поддерживаются поля очереди, статуса, приоритета, исполнителя, автора,
проекта, спринта, тегов, дедлайна, оценки и текста; функции `currentUser()`,
`today()`, `endOfWeek()`, `endOfMonth()`, `empty()`. Разбор идёт рекурсивным
спуском в условие Prisma — значения нигде не склеиваются в SQL.

### Отчёты

Считаются из данных, а не из констант: время цикла — по разнице между
созданием и закрытием, соблюдение сроков — по доле задач, закрытых до
дедлайна, пропускная способность — по фактическим закрытиям за неделю.
Burndown складывается из ежедневных срезов остатка story points; срез
снимает фоновое задание вместе с прогоном правил по расписанию.

## Команды

```bash
npm run dev
```

Поднимает сервер и клиент вместе.

```bash
npm run build && npm start
```

Собирает фронтенд и запускает один процесс, который отдаёт и API, и статику.

Остальное: `npm run seed -- --force` — перенаполнить базу, `npm run db:studio`
— просмотр данных, `npm run db:reset` — сброс схемы, `npm run typecheck` —
проверка типов клиента и сервера.

## Дизайн-система

Все значения — в [`src/styles/tokens.css`](src/styles/tokens.css); ни один
компонент не использует сырые цвета. Четыре уровня поверхностей, акцент и пять
семантических цветов в OKLCH, IBM Plex Sans и IBM Plex Mono, радиусы 4–12 px,
четыре уровня теней, восемь именованных анимаций. Тёмная тема переопределяет
только переменные — разметка у обеих тем общая. При включённом
`prefers-reduced-motion` анимации отключаются.

Цвета и иконки для статусов, приоритетов и людей сервер отдаёт именами
переменных, поэтому переключение темы остаётся полностью на стороне клиента.

## База данных

По умолчанию SQLite: файл `prisma/dev.db`, никаких внешних сервисов. Переход
на PostgreSQL — это смена `provider` и `DATABASE_URL` в
[`prisma/schema.prisma`](prisma/schema.prisma) и `npx prisma migrate dev`;
запросы в коде писать заново не нужно.

Перечислений в схеме нет намеренно: SQLite их не поддерживает, поэтому роли,
статусы и категории хранятся строками и проверяются в
`server/lib/constants.ts`.

## Переменные окружения

Скопируйте `.env.example` в `.env`:

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | Строка подключения, по умолчанию `file:./dev.db` |
| `JWT_SECRET` | Подпись токенов; в продакшене обязателен, не короче 16 символов |
| `PORT` | Порт API, по умолчанию 4180 |
| `UPLOAD_DIR` | Каталог вложений, по умолчанию `uploads/` |

## Доступность

Все интерактивные элементы — настоящие `button`, `input`, `select` и
`textarea` с видимым фокусным кольцом. Чекбоксы и переключатели снабжены
`role`, `aria-checked` и `aria-label`, вкладки — `role="tab"`, модальные окна
— `role="dialog"` и `aria-modal`, диаграммы помечены `role="img"` с описанием,
уведомления объявляются через `aria-live`.
